## Decisions adopted in this plan

No CONTEXT.md exists for this phase, so each open question is closed here as a stated
assumption rather than deferred to the executor.

| # | Question | Position adopted | Why |
|---|---|---|---|
| D-H | How are the privacy annotations written, and what is verified? | **Every interpolated value in a log call carries an explicit privacy annotation. The edition id, chapter file id and HTTP status are annotated public; nothing else in the download path is logged at all.** | `os.Logger` redacts non-static values by default, but numeric types are already public without an annotation — so writing the annotation is about self-documentation and about surviving a future type change that would otherwise start redacting a field silently. Annotating explicitly makes the intent reviewable in the diff, which is the only place LOG-03 can actually be checked. |
| D-I | How is "readable, not redacted" verified? | **By `xcrun simctl install` + `xcrun simctl launch`, never by Xcode's Run or Debug button.** | Xcode sets `OS_ACTIVITY_DT_MODE` on any process it launches or attaches to, which disables redaction at write time for every field regardless of annotation. Under that condition a plaintext credential and a correctly-annotated integer look identical in the console, so an Xcode-driven check proves nothing. A `simctl launch` with no debugger attached keeps normal redaction in force, which makes both directions of the check meaningful: a public field shows its value, and a field that should have stayed private visibly does not. |
| D-J | What may be interpolated into a log line? | **Opaque integer identifiers and status codes, and an error's localized description. Never a bare error value, never a URL, never a credential.** | `ManifestChapter.url` is a server-signed, time-limited grant, per the downloader's own comments about a grant lasting seven days and a rotated server secret — logging it, even annotated public, is exactly the credentialed URL LOG-03 forbids. The subtler leak is indirect: a `URLError`'s debug representation embeds the failing URL, so interpolating the error value itself would smuggle the grant into the log even though no URL appears in the source line. Interpolating the localized description instead yields a short localized phrase with no URL. The tree currently contains zero bare-error interpolations, so this is an invariant to preserve, not a cleanup. |
| D-K | Which `try?` sites does this plan touch? | **Only `ChapterDownloader.swift`'s single site.** The other eight are plan 01-03's. | Keeps the file ownership disjoint so the two plans cannot conflict, and keeps this plan's diff small enough that the LOG-03 credential review is a real review. |
| D-L | How many in-scope `try?` sites are there? | **Nine, not eleven.** | RESEARCH.md states "9 sites total, plus AudiobookPlayer's own 2 — 11 sites", but its own file:line enumeration lists AudiobookPlayer's two *inside* the nine. A grep at planning time confirms exactly nine occurrences across the four in-scope files: `ChapterDownloader.swift` 1, `FileStore.swift` 5, `AudiobookPlayer.swift` 2, `AppModel.swift` 1. This plan owns 1 of them; plan 01-03 owns the other 8. The discrepancy is recorded rather than silently resolved, because a verifier counting to 11 would otherwise report a false gap. |
